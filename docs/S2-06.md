## Implementation and acceptance evidence

| Criterion | Implementation / checks |
| --- | --- |
| Available previews play | `JustAudioPreview` streams HTTPS with a native clipped audio source (maximum 30 seconds); actual shorter duration is respected. URL survives JSON -> Drift -> view model. |
| Controls work | Shared player supports play, pause/resume, completion/replay, track switch and stop. Position comes from the decoder. Scan card and Album Details share state. App backgrounding pauses without auto-resume. |
| Unavailable previews | Missing/invalid URLs disable controls; album details remain accessible. Loading/buffering state, 15-second load timeout, safe error message and retry for failed playable URLs. Error snackbar plus inline feedback. |
| Ordering when possible | Known ranks first; ties and unranked tracks retain release order; at most five playable tracks in the scan card. No manufactured ranks or "Popular" label on unranked previews. Full details tracklist retains release order. |

Each selected source gets its own disposable audio adapter. Previous audio is
released before a replacement loads; generation checks ignore stale loads,
errors and events. Pause during loading cancels playback intent. Stop and
app disposal cannot resurrect a pending preview. No audio cache, background
service, API key, or backend provider changes are introduced.

`Track.hasPreview` now requires a usable HTTPS URL (the optional existing
`hasPreview: false` override still disables a track). The mock catalogue has
no real URLs and correctly shows unavailable instead of pretending to play.
Tests use explicit fixture URLs and an injected audio adapter.

Dependency: `just_audio` 0.10.6, locked with its transitive dependencies.
Android INTERNET permission is in the main manifest, including release builds.
No cleartext allowance is needed. API usage follows the
[package documentation](https://pub.dev/packages/just_audio).

## Validation

From `mobile/`:

```sh
flutter pub get --enforce-lockfile
dart format --output=none --set-exit-if-changed lib test tool
flutter analyze
flutter test
flutter build apk --debug
```

Player tests cover pause/resume, bounded progress, shorter clips, replay,
buffering, switching, stop, invalid URLs, load/runtime failures, retry,
timeout, pause while loading, stale completion and disposal. Widget tests
cover the scan card, Album Details, mini-player, disabled controls, loading,
retry, stop and app lifecycle. The S2-05 database test checks URL preservation
and unranked fallback through real SQLite storage.

Optional Android smoke test (network required):

```sh
flutter run -d <android-device> -t tool/preview_smoke.dart
```

This separate development entrypoint queries public iTunes previews and uses
the production player/UI. It prints assertions for decoder progress,
pause/resume, switching (when a second preview exists), bounded completion,
replay and stop. It does not alter default app startup or test S2-07 wiring.
A final `S2-06 SMOKE PASSED` marker is required; a build alone is not playback
proof. Audible output still needs a human listening check.
