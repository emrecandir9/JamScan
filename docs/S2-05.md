# S2-05: extend the album data model

Owner: Olena. Reviewer: Oliver. Estimate: 5 SP. Branch: `feature/S2-05-extend-data-model`.

> As a developer, I want the local data model to store the extended Discogs
> metadata so that Album Details can show it and previously fetched albums
> load from cache.

Acceptance criteria: Drift tables gain the fields Album Details needs (label,
catalogue number, genres and styles, rating; track duration and position);
fetched metadata is cached locally; existing data survives the migration.

## What changed

| Checklist item | Where |
| --- | --- |
| Review the existing schema | Gaps listed in `UI_SHELL.md` and the S2-04 response compared field by field |
| Label and catalogue number | `albums.label`, `albums.catalog_number` |
| Genres, styles and rating | `albums.genres`, `albums.styles` (JSON arrays), `albums.rating` |
| Track duration and position | `tracks.duration_seconds`, `tracks.position_label` (`A1`); `tracks.position` keeps the order |
| Migration | `schemaVersion` 1 → 2, `onUpgrade` adds the columns |
| Local caching | `lib/data/release_repository.dart`, 7-day freshness, offline fallback |
| DAOs and mapping | `AlbumDao.saveRelease`, `AlbumDao.getReleaseWithTracks`, `lib/data/release_metadata.dart` (JSON → rows), `lib/data/local/album_mapping.dart` (rows → `Album` view model) |
| Tests | `test/data/extended_metadata_test.dart` (19 tests, 69 in total) |
| Documentation | `DATA_MODEL.md` decisions 5 and 6, ER diagram (Mermaid and draw.io) |

Also stored, because the backend returns them and the screens need them:
`albums.cover_url` (remote cover) and `albums.preview_status`.

Design decisions and the cache rules are explained in
[DATA_MODEL.md](DATA_MODEL.md) (decisions 5 and 6).

## How S2-07 uses it

```dart
final repository = ReleaseRepository(db, (releaseId) async {
  // GET {backend}/releases/{releaseId}, decoded as JSON.
});
final result = await repository.load(candidate.releaseId);
final album = result.release.toViewModel(isPartial: result.isStale);
// Open Album Details with `album`.
```

`load` throws when the backend fails and nothing is cached; the screen shows
the unavailable state in that case.

## Not included

- `albums.country` and the rating count: the S2-04 response does not return
  them yet.
- Track popularity: neither Discogs nor iTunes returns it, so
  `Album.topTracks` is empty for fetched albums. S2-06 (previews) needs to
  decide the order of the top tracks.
- The HTTP client for the backend: part of S2-07.
