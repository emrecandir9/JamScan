# S2-10: best-frame capture and cover preprocessing

Owner: Emre. Branch: `feature/S2-10-best-frame-capture` (built on S2-09).

> As a user, I want the app to pick a good picture of each album by itself,
> so that recognition starts without me taking a photo.

Requirements covered: FR-04 (automatic recognition without manual capture),
the FURPS item on preprocessing captures (cropping, downsampling), the
§4.4.7 rule against resubmitting an album that stays in view, and the
"too blurry or dark" exception flow. Status on **2026-10-19**: implemented
and tested. Recognition results reach the screen through S2-11.

## How it works

For every visible, tracked cover (`vision/best_frame_selector.dart`):

1. **Quality** (`vision/frame_quality.dart`), measured inside the cover on
   the 320-px analysis frame:

   | Measure | Meaning | Full score at | Zero at |
   | --- | --- | --- | --- |
   | Sharpness | variance of the Laplacian | ≥ 160 | ≤ 20 |
   | Highlights | grey level of the brightest 5 % | ≥ 90 | ≤ 30 |
   | Overexposure | mean grey level | ≤ 215 | ≥ 245 |
   | Glare | share of near-white pixels | ≤ 5 % | ≥ 40 % |
   | Size | cover area / frame | ≥ 15 % | ≤ 4 % |
   | Skew | worst corner angle vs 90° | ≤ 15° | ≥ 40° |
   | Motion | corner movement / cover size | ≤ 0.01 | ≥ 0.08 |

   The score is the product. Exposure uses highlights rather than the mean,
   so a black sleeve (Joy Division) is not mistaken for a dark photo. Each
   cover also gets a hint (`holdSteady`, `tooDark`, `glare`, `blurry`,
   `moveCloser`) for the UI.
2. **Best view**: the highest-scoring frame of each cover is kept, in full
   resolution.
3. **When to capture**: once the cover has been seen in 3 frames, is still
   (motion ≤ 0.03) and its best view scores ≥ 0.5. Otherwise after 12
   frames (about 2.5 s) if the best view scores ≥ 0.2. Covers touching the
   frame edge are never captured.
4. **Flattening** (`vision/cover_crop.dart`): a homography maps the
   cover's four corners to an upright 512 × 512 square. Pixels come
   straight from the full-resolution YUV frame (BT.601 to RGB), and the
   sensor rotation is undone so the cover reads the right way up. The crop
   is encoded as JPEG (quality 90).
5. **Duplicates**: each cover is captured once while it stays tracked. Each
   crop also carries a 64-bit difference hash. Photos of the same cover
   differ by ≤ 10 bits and different covers by > 16 in tests, so the session
   (S2-11) can skip an album that leaves and comes back.

Manual photos and gallery imports use the same steps
(`vision/still_cover.dart`): find the largest cover not touching the edge,
flatten it, and measure its quality. Without an outline, the centre 90 %
square is used.

## Validation

| Check | Result |
| --- | --- |
| `flutter analyze` | No issues |
| `flutter test` | 92 passed |
| Selection tests | still sharp cover captured exactly once, at frame 3; moving cover waits (hint `holdSteady`) and is captured once still; sharpest view is the one sent; blurry cover never captured (hint `blurry`); cut-off cover never captured |
| Crop tests | tilted cover flattened right way up; 90° sensor frame turned upright; difference hashes separate same and different covers |
| Still photos | cover found and flattened in a JPEG; centre fallback without an outline; unreadable bytes rejected |
| Live pipeline on real covers (local-only test, simulated 1280 × 720 YUV frames, sensor at 90°) | 33/42 captured; 31/39 of the covers fully in frame; median 3 analysed frames per capture |
| Those 33 crops through the backend recognizer (S2-03) | 33/33 correct first answer; 30 auto-matched, 2 needs review (right album listed), 1 no match; 0 wrong matches |

The local proof test writes its crops to `mobile/build/capture_proof/`;
`python -m scripts.evaluate_recognition ../mobile/build/capture_proof`
(backend, S2-03 evaluation branch) scores them.

## Known limitations

- The thresholds above are set on synthetic scenes. They need checking on a
  phone: real sensor noise and focus change sharpness values.
- A cover missed by the detector (S2-09 limitations) is never captured
  automatically; manual capture remains the fallback (FR-11).
- JPEG encoding of the crop runs in pure Dart in the analysis isolate. It
  happens once per cover, and its speed on a phone has not been measured yet.
