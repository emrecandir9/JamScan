## Implementation details

Camera handling is isolated in:

```text
mobile/lib/services/camera_capture_service.dart
```

The service uses the existing Flutter `image_picker` dependency for camera
access and `permission_handler` for runtime camera permissions.

The camera is opened using:

```dart
final photo = await _picker.pickImage(
  source: ImageSource.camera,
  requestFullMetadata: false,
);
```

The following camera result states are supported:

```text
captured
cancelled
permissionDenied
permissionPermanentlyDenied
failed
```

The user interface is implemented in:

```text
mobile/lib/screens/camera_capture_screen.dart
```

The screen stores the selected photo path and displays the result using the
shared image-preview area.

When no image has been captured, the main action is:

```text
Photograph cover
```

After a successful capture, the action becomes:

```text
Retake photo
```

A successful capture displays:

```text
Cover photo captured.
```

If the user cancels the camera workflow, JamSCAN displays:

```text
Capture cancelled.
```

If camera permission is denied, the application displays:

```text
Camera permission is needed to photograph the cover.
```

If permission is permanently denied, the application displays:

```text
Enable camera permission in JamSCAN settings.
```

and provides an:

```text
Open settings
```

action.

If the capture operation fails, the application displays:

```text
Could not capture the photo. Please try again.
```

Permission and failure conditions therefore provide specific feedback instead
of failing silently.

## Android process-death recovery

Android may terminate the application process while an external camera
application is open.

To handle this case, S1-03 checks `ImagePicker.retrieveLostData()` when the
capture screen starts.

If Android returns a previously captured image, JamSCAN restores the image and
displays it in the normal preview instead of losing the result.

This behaviour was manually validated by terminating the background JamSCAN
process while the camera remained open and then confirming the photograph.
JamSCAN reopened and displayed the recovered capture.

The recovery workflow is therefore:

```text
JamSCAN
   ↓
Photograph cover
   ↓
Android camera opens
   ↓
JamSCAN process terminated in background
   ↓
Photo confirmed in camera
   ↓
JamSCAN restarts
   ↓
retrieveLostData()
   ↓
Captured image restored
   ↓
Preview displayed
```

## Dependencies

S1-03 uses:

```text
image_picker: ^1.2.3
permission_handler: 12.0.1
```

`permission_handler` was pinned to `12.0.1` to retain compatibility with the
project's Android build configuration at the time of implementation.

A newer version tested during development required a newer Android compile SDK.

No additional package was introduced for image preview or lost-capture
recovery.


S1-04 does not replace S1-03. It extends the existing capture screen while
preserving the camera workflow and its tests.

continued to pass after gallery functionality was introduced.
