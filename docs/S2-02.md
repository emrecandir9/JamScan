# S2-02: reference dataset and embeddings

Owner: Olena. Reviewer: Emre. Estimate: 5 SP. Branch: `feature/S2-02-reference-dataset`
(based on `feature/S2-03-recognition-evaluation`, which provides the model,
`build_index` and the index format).

> As a developer, I want to prepare a fixed dataset of vinyl album covers and
> their image embeddings so that the recognition algorithm can compare
> captured images with known albums efficiently.

Acceptance criteria: a reference dataset containing album covers,
identifiers, and image embeddings is prepared; album entries are consistently
indexed and retrievable; the dataset can be used by the recognition component.

## Supported albums

`backend/datasets/reference_albums.csv` defines the fixed set the MVP
recognises: **154 vinyl albums** (`artist,title,release_id`).

- The 42 development albums from S2-03, with their Discogs release IDs
  already pinned, so the S2-03 results stay comparable.
- 112 new albums chosen to cover rock, pop, hip-hop, soul, jazz, electronic
  and French music (records likely to be found in local shops for the demo).
- Deliberate look-alikes from the same artists (for example several Beatles,
  Bowie, Radiohead, Metallica and Led Zeppelin albums). They test whether the
  matcher separates similar artwork rather than only very different covers.
- Known hard covers: *The Beatles* (almost all white) and *Metallica* (almost
  all black). They are kept on purpose and checked in the confusable-pairs
  report below.

The Notorious B.I.G., *Ready To Die* was in the first draft but was removed:
Discogs vinyl search returned no release with a cover for it.

Release IDs of the new albums are filled automatically the first time the
dataset is fetched (`--save-ids`) and committed, so every later run downloads
exactly the same releases.

To add an album the team can photograph, append `artist,title,` to the list
and run the steps again. Real phone photos for the S2-03 evaluation should be
taken of albums in this list.

## Dataset layout

The dataset folder follows the format S2-03 expects:

```text
data/reference/
  covers.csv            release_id,artist,title,year,image
  images/<release_id>.jpg
```

- `release_id` is the Discogs release ID and is the key used everywhere:
  in the index, by the recognition endpoint, and by the S2-04 metadata
  endpoint.
- `year` is the year of the pinned pressing, which may be a reissue year.
- Cover art is copyrighted, so `backend/data/` stays out of Git. What is
  committed is the album list (with IDs) and the validation report with the
  dataset fingerprint, which is enough to rebuild an identical dataset.

## Embeddings and index

The embedding approach was chosen with Emre in S2-03: DINOv2-small (ONNX,
CPU), class token, L2-normalised to 384 numbers, same preprocessing for
reference covers and query photos. `scripts.build_index` writes:

- `data/index/embeddings.npy`: one unit-length row per cover.
- `data/index/manifest.json`: model and preprocessing version plus one entry
  per row (`release_id`, artist, title, year, image).

Retrieval: `ReferenceIndex.search()` ranks releases by cosine similarity.
This story adds lookup by ID: `release_ids()`, `get(release_id)` and
`vectors_for(release_id)`, so any indexed album can be retrieved directly.

## Build it

From `backend/` with the virtual environment active and `DISCOGS_TOKEN` set
(PowerShell: `$env:DISCOGS_TOKEN="..."`):

```bash
python -m scripts.download_model
python -m scripts.fetch_dev_covers --albums datasets/reference_albums.csv --output data/reference --save-ids
python -m scripts.build_index --dataset data/reference --output data/index
python -m scripts.validate_dataset --dataset data/reference --index data/index \
    --albums datasets/reference_albums.csv --report ../docs/evidence/S2-02-dataset-report.json
```

Fetching respects the Discogs limit of 60 requests per minute, so the first
run takes about 8 to 10 minutes. Later runs skip images that already exist.

## Consistency checks

`scripts/validate_dataset.py` exits with an error when:

- `covers.csv` lacks a column, a `release_id` is not numeric, artist or title
  is empty, or a year is implausible;
- one release appears under two different names;
- an image is missing, unreadable, outside the dataset folder, listed twice,
  or byte-identical to the cover of another release;
- the index does not list the same rows as `covers.csv` in the same order
  (stale index), has non-finite or non-unit embeddings, or a release cannot
  be looked up or does not rank first for its own cover.

It warns (without failing) about images smaller than 300 px, images not
listed in `covers.csv`, supported albums that could not be fetched, and
pairs of different releases whose covers score 0.90 or more
(`confusable_pairs`). The report also contains a SHA-256 fingerprint of the
rows and image bytes: two team members with the same fingerprint have the
same dataset.

Automated tests: `tests/test_validate_dataset.py` (11 tests, synthetic
images and a fake embedder, so CI needs neither Discogs nor the model).

## Results

First full build on **2026-10-20** (Windows laptop, CPU):

| Item | Value |
| --- | --- |
| Albums in the supported list | 154 |
| Covers fetched / skipped | 154 / 0 |
| Index rows, dimension | 154 × 384 |
| Model, preprocessing | `dinov2-small/cls/v1`, `square-224-imagenet-v1` |
| Errors / warnings | 0 / 3 |
| Confusable pairs (≥ 0.90) | 0 |
| Dataset fingerprint | `b6a027c1bbf1694a86be4fadac5d5b5632942a54e0169bde2d739fa35e54e190` |

- Every release is retrievable by its ID and ranks first for its own cover.
- No two different albums score 0.90 or more, including the look-alike
  albums by the same artist and the all-white / all-black covers.
- The 3 warnings are covers smaller than 300 px: John Coltrane, *A Love
  Supreme* (222 px), Frank Ocean, *Channel Orange* (225 px) and The Rolling
  Stones, *Let It Bleed* (280 px). The model input is 224 × 224, so they are
  still usable. If S2-03 finds them weak on real photos, add a second, larger
  reference image for these releases.

Evidence: [dataset report](evidence/S2-02-dataset-report.json).
