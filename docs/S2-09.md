# S2-09: live camera preview and album-cover detection

Owner: Emre. Branch: `feature/S2-09-live-cover-detection`.

> As a user, I want the camera to find album covers by itself and outline
> them, so that I can scan records without taking photos.

Requirements covered: FR-01 (continuous live preview), FR-02 (automatic
cover detection), FR-03 (visible outline). The backlog item is proposed in
the Sprint 1 review (§4.4.3); the team still has to add it to the board.

Status on **2026-10-19**: implemented, unit-tested, and checked on the
Android emulator. Not yet tried on a physical phone.

## How it works

```text
camera stream (YUV, 1280×720) ─► every 200 ms, if the worker is free
  ─► background isolate: downscale luma to 320 px ─► detect covers ─► track
  ─► main isolate: CustomPaint outlines over CameraPreview
```

- **Camera** (`services/live_scanner.dart`): `CameraLiveScanner` uses the
  `camera` plugin (CameraX on Android) with `ResolutionPreset.high` and a
  YUV image stream. Frames arriving while the worker is busy are dropped, so
  the preview never lags. The same controller takes the photo when the user
  presses the shutter. Without a usable camera, the page falls back to the
  system camera (S1-03). Analysis pauses while another page is on top, and
  the camera stops when the Scan tab is left or the app goes to the
  background.
- **Detection** (`vision/cover_detector.dart`, plain Dart, no plugins): blur,
  Sobel gradients and three edge maps (two percentile thresholds and a Canny
  map). Each map is used twice: as connected edge regions, and as filled
  closed shapes after a morphological opening that removes thin lines such
  as table seams. Each region's convex hull is reduced to four corners
  (restoring a clipped corner when that is cheap). A quad is kept when its
  size, aspect ratio (0.6–1.65), corner angles (55–125°), fit to the region,
  and edge support along its sides look like a sleeve. Near-duplicates keep
  the best fit, and outlines nested inside a larger one are dropped. Up to
  three covers per frame.
- **Tracking** (`vision/cover_tracker.dart`): matches covers between frames
  by overlap, gives each a stable id, smooths corners, measures motion
  (used by S2-10), and keeps a cover through up to three missed frames.
- **Overlay** (`widgets/live_camera_view.dart`): maps corners from sensor
  orientation to the upright preview and through `BoxFit.cover` to screen
  pixels. Green means the cover is fully in view; yellow means it touches the
  frame edge, so it is not captured.

OpenCV (`opencv_dart`) was the first plan. Its native build needs full Xcode
for host tests, so the same classical steps are written in Dart instead.
They are testable everywhere, add nothing to the APK, and can be swapped for
OpenCV behind `CoverDetector` later.

## Validation

| Check | Result |
| --- | --- |
| `flutter analyze` | No issues |
| `flutter test` | 79 passed (50 existing + 29 new) |
| Synthetic scenes (known corners) | frontal, tilted, three covers, nested frame, cut-off cover: all found within 2–2.5 % corner error; thin strips and empty scenes rejected |
| Real covers (local-only test, 42 Discogs covers × 2 backgrounds, random tilt and perspective) | 75/84 found (89.3 %), median corner error 1.56 % of frame width |
| False covers in 40 empty table/wall scenes | 0 |
| Detection time, 320 × 240, host | about 20 ms per frame (JIT, debug test) |
| Android emulator, camera fed a table scene with two covers | live preview, Rumours outlined; 13 ms per frame in a debug build, about 4.5 analysed frames per second |

The real-cover test needs the covers fetched by
`backend/scripts/fetch_dev_covers.py` and skips itself otherwise (cover art
is not committed). It writes annotated images to
`mobile/build/vision_proof/`.

To try it on the emulator, feed the back camera an image of covers:

```bash
emulator -avd Pixel_9 -camera-back imagefile:/path/to/scene.png
```

## Known limitations

- A straight background line (table seam, shelf edge) running within about
  10 px of a cover's side can merge with it. That side is then a few percent
  off, or the cover is missed in that frame. On the emulator the outline
  covered about 85 % of a cover whose border lay on a plank seam.
- Covers touching each other (sleeves in a crate) merge into one region and
  are not separated.
- A light cover on a light background can lose one side; the cover is then
  missed in that frame.
- Covers smaller than 6 % of the frame are ignored (too far away to
  recognise reliably).
